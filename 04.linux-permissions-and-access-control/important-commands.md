To locate and fix files or directories with globally writable `777` permissions, you will use the `find` command paired with the `-perm` flag. Because directories and regular files require different default permissions, you must target and fix them separately.

### 1. Audit First (Find without modifying)

Before changing anything, it is best practice to generate a list of the exposed files and directories so you know exactly what is about to be modified.

**Find directories with 777 permissions:**

```bash
sudo find /path/to/target -type d -perm 0777 -ls

```

**Find regular files with 777 permissions:**

```bash
sudo find /path/to/target -type f -perm 0777 -ls

```

*(The `-ls` flag formats the output to show you the current owner, size, and modification date alongside the file path).*

### 2. The Fix (Find and Repair)

Once you have verified the target path, use the `-exec` flag to automatically apply the correct, secure permissions to the vulnerable items.

**Fix Directories (Change 777 to 755):**
This keeps the directories accessible and searchable for everyone, but restricts write/delete access exclusively to the owner.

```bash
sudo find /path/to/target -type d -perm 0777 -exec chmod 755 {} +

```

**Fix Files (Change 777 to 644):**
This completely removes the dangerous execute bit and restricts write access to the owner, while allowing others to read the files.

```bash
sudo find /path/to/target -type f -perm 0777 -exec chmod 644 {} +

```

### Understanding the `-perm` filter

* `-perm 0777`: Searches for an **exact match**. It will only find files that are exactly `rwxrwxrwx`.
* `-perm -0777`: Adding a hyphen before the number means **"at least"**. It will find files that have 777 permissions, even if they also have special bits set (like a sticky bit or SUID). For general cleanup, the exact match (`0777` without the hyphen) is usually safer to start with.

* ---

* Finding SUID and SGID files is a standard security auditing task. These special permissions allow an executable file to run with the privileges of the file's owner (SUID) or group (SGID), rather than the user who is actually running it.

Because these files can temporarily grant high-level (often root) access, attackers actively look for them.

Here are the commands to locate them across your entire file system.

### 1. Find Files with SUID (Set User ID)

The SUID bit is represented by the octal value `4000`.

```bash
sudo find / -type f -perm -4000 -ls 2>/dev/null

```

### 2. Find Files with SGID (Set Group ID)

The SGID bit is represented by the octal value `2000`.

```bash
sudo find / -type f -perm -2000 -ls 2>/dev/null

```

### 3. Find BOTH in a Single Command

To hunt down any file that has *either* the SUID or SGID bit set, combine the values (4000 + 2000 = 6000) and use the `/` modifier:

```bash
sudo find / -type f -perm /6000 -ls 2>/dev/null

```

### Understanding the Syntax

* **`-perm -4000`**: The hyphen (`-`) means "find files that have **at least** this bit set." It will match a file whether its permissions are `4755` or `4777`.
* **`-perm /6000`**: The slash (`/`) means "find files that have **any** of these bits set." It will match files with SUID (4000), SGID (2000), or both (6000).
* **`2>/dev/null`**: This is crucial when searching from the root directory (`/`). It silences the massive wall of "Permission denied" errors generated by virtual file systems (like `/proc`), keeping your results clean.

* ---

* The sticky bit is a special permission primarily used on shared directories. When applied, it ensures that only the file's owner (or the root user) can delete or rename files within that directory, even if the directory itself has `777` (full read/write) permissions.

The octal value for the sticky bit is `1000`.

Here is the command to locate all directories across your file system that have the sticky bit set:

```bash
sudo find / -type d -perm -1000 -ls 2>/dev/null

```

### Understanding the Syntax

* **`-type d`**: Filters the search to exclusively look for directories. (The sticky bit is rarely useful on regular files in modern Linux).
* **`-perm -1000`**: The hyphen (`-`) means "find directories that have **at least** this bit set." It will successfully match a directory whether its permissions are `1777` (like `/tmp`), `1755`, or any other combination that includes the sticky bit.
* **`2>/dev/null`**: Silences the "Permission denied" errors that naturally occur when searching the root filesystem.

> **Common System Defaults:** When you run this command, it is completely normal to see directories like `/tmp`, `/var/tmp`, and `/dev/mqueue` in the results. These are system-critical shared folders that rely on the sticky bit to prevent users from deleting each other's temporary files. Do not modify the permissions on these core directories.
>
> ---
>
> Setting or removing special permissions is done using the `chmod` command, just like standard permissions. You can do this using either the **symbolic method** (letters like `+s`, `-t`) or the **numeric method** (adding a fourth octal digit like `4000` to the front of your permissions).

When checking permissions with `ls -l`, these special bits replace the standard execute (`x`) bit in the owner, group, or others column. If the letter is lowercase (`s` or `t`), it means the underlying execute bit is also set. If it is uppercase (`S` or `T`), the execute bit is missing.

---

### 1. SUID (Set User ID)

The SUID bit forces an executable file to run with the permissions of the file's *owner*, rather than the user running it.

* **Symbolic:** Use `u+s` to add, and `u-s` to remove.
* **Numeric:** Add `4000` to the base permissions.

**Examples:**

```bash
# Apply SUID (Symbolic)
sudo chmod u+s /usr/local/bin/custom-script

# Apply SUID to a 755 file (Numeric)
sudo chmod 4755 /usr/local/bin/custom-script

# Remove SUID
sudo chmod u-s /usr/local/bin/custom-script

```

### 2. SGID (Set Group ID)

On an executable, SGID runs the file with the file's group privileges. On a directory, it forces any new file created inside to inherit the directory's group, making it essential for shared team folders.

* **Symbolic:** Use `g+s` to add, and `g-s` to remove.
* **Numeric:** Add `2000` to the base permissions.

**Examples:**

```bash
# Apply SGID to a shared directory (Symbolic)
sudo chmod g+s /srv/projects/dev

# Apply SGID to a 770 directory (Numeric)
sudo chmod 2770 /srv/projects/dev

# Remove SGID
sudo chmod g-s /srv/projects/dev

```

### 3. Sticky Bit

The sticky bit is applied to directories (like `/tmp`) to ensure that only a file's owner can delete or rename the files inside it, even if the directory itself is fully writable (`777`) by everyone.

* **Symbolic:** Use `+t` to add, and `-t` to remove.
* **Numeric:** Add `1000` to the base permissions.

**Examples:**

```bash
# Apply Sticky Bit (Symbolic)
sudo chmod +t /var/shared-temp

# Apply Sticky Bit to a 777 directory (Numeric)
sudo chmod 1777 /var/shared-temp

# Remove Sticky Bit
sudo chmod -t /var/shared-temp

```
