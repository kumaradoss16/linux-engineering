# Basic `kill` and `pkill` Commands in Linux

The `kill` and `pkill` commands send signals to processes. They are commonly used to terminate programs, stop unresponsive applications, and manage background tasks.

The key difference:

- `kill` targets a process using its PID (Process ID).
- `pkill` targets processes using a name or other matching criteria.

## 1. Basic `kill` commands

| Command           | Purpose                                 |
| ----------------- | --------------------------------------- |
| `kill 1234`       | Sends `SIGTERM` to PID 1234 by default. |
| `kill -TERM 1234` | Requests graceful termination.          |
| `kill -KILL 1234` | Forces termination using `SIGKILL`.     |
| `kill -STOP 1234` | Suspends a process.                     |
| `kill -CONT 1234` | Resumes a stopped process.              |
| `kill -l`         | Lists signal names.                     |

### Example 1: Terminate a process

First, find the PID:

```
pgrep -af python3
```

Suppose the output shows PID `4567`. Request termination:

```
kill 4567
```

By default, `kill` sends `SIGTERM` (signal 15), allowing the process to clean up and exit.

### Example 2: Force termination

```
kill -KILL 4567
```

`SIGKILL` (signal 9) forces the kernel to terminate the process. The process cannot catch or ignore it.

Best practice: Try `SIGTERM` first. Use `SIGKILL` only if the process does not terminate and you have confirmed that forcing it is appropriate.

## 2. Basic `pkill` commands

| Command                         | Purpose                                              |
| ------------------------------- | ---------------------------------------------------- |
| `pkill firefox`                 | Sends `SIGTERM` to processes matching `firefox`.     |
| `pkill -TERM python3`           | Requests graceful termination of matching processes. |
| `pkill -KILL process_name`      | Forcefully terminates matching processes.            |
| `pkill -STOP process_name`      | Suspends matching processes.                         |
| `pkill -CONT process_name`      | Resumes matching processes.                          |
| `pkill -u student process_name` | Targets matching processes owned by user `student`.  |
| `pkill -x bash`                 | Matches the exact process name `bash`.               |

### Example 1: Terminate a process by name

```
pkill firefox
```

This sends `SIGTERM` to matching processes named `firefox`, subject to the command's matching rules and your permissions.

Unlike `kill 1234`, you don't need to know the PID first.

### Example 2: Match an exact process name

```
pkill -x sleep
```

The `-x` flag requires the process name to match exactly, rather than merely matching a name pattern.

### Example 3: Target a process owned by a specific user

```
pkill -u student -x python3
```

This targets processes named exactly `python3` that belong to the user `student`.

Caution: `pkill` can match multiple processes. Check the targets before terminating them, especially on shared or production systems.

## 3. Difference between `kill` and `pkill`

| Feature            | `kill`                                      | `pkill`                                     |
| ------------------ | ------------------------------------------- | ------------------------------------------- |
| Target             | PID                                         | Process name or matching criteria           |
| Example            | `kill 4567`                                 | `pkill -x python3`                          |
| Multiple processes | Possible with multiple PIDs                 | Can match multiple processes automatically  |
| Default signal     | `SIGTERM`                                   | `SIGTERM`                                   |
| Package            | Usually provided by shell or core utilities | Commonly provided by `procps` / `procps-ng` |

## 4. Practical workflow

Suppose you started a Python script in your Linux lab and need to stop it.

Step 1 — Find the process

```
pgrep -af signal_demo.py
```

Step 2 — Inspect the process

```
ps -p 4567 -o pid,ppid,user,stat,cmd
```

Replace `4567` with the actual PID.

Step 3 — Request termination

```
kill -TERM 4567
```

Step 4 — Verify termination

```
ps -p 4567
```

If no process is listed, that PID no longer identifies a running process.

## 5. Important signal names to remember

| Signal    | Number on Linux                  | Meaning                                   |
| --------- | -------------------------------- | ----------------------------------------- |
| `SIGHUP`  | 1                                | Hangup                                    |
| `SIGINT`  | 2                                | Interrupt, commonly generated by `Ctrl+C` |
| `SIGKILL` | 9                                | Force termination                         |
| `SIGTERM` | 15                               | Request termination                       |
| `SIGSTOP` | 19 on common Linux architectures | Stop a process                            |
| `SIGCONT` | 18 on common Linux architectures | Resume a stopped process                  |

Use names such as `SIGTERM` and `SIGKILL` when possible because signal numbers can vary across operating systems.

One final distinction: `kill` and `pkill` send signals; they do not inherently terminate a process. The effect depends on the signal. For routine process management, start with `kill PID` or `pkill -x process_name`, both of which normally request graceful termination.
